# 皮肤健康检测 · 人脸皮肤分析报告

一个**零依赖、纯前端**的网站：请求摄像头权限 → 实时人脸引导 → 多帧采集 → 在本机逐像素分析皮肤 → 生成可导出的皮肤健康报告。

视频帧与照片**不会离开浏览器**，没有后端、没有第三方分析 SDK、没有 CDN。

---

## 快速开始

```bash
node serve.mjs          # 默认 http://127.0.0.1:5173/
node serve.mjs 8080     # 指定端口
```

> **为什么必须用本地服务器？**
> 浏览器只在"安全上下文"（`https://` 或 `http://localhost`）下才允许网页访问摄像头。
> 直接双击 `index.html`（`file://`）在部分浏览器中会被拒绝，所以请用上面的命令起一个本地服务。

也可以用任意其他静态服务器（`python -m http.server`、`npx serve` 等）指向本目录。

## 分享给同一网络下的其它设备（手机 / 电脑）

别人打不开的原因有三个，都已解决，但其中一步需要你亲手操作：

**1. 服务器已监听所有网卡**（`0.0.0.0`），启动时会打印局域网地址（如
`http://10.234.119.114:5173/`），同一 Wi-Fi 下的设备理论上都能访问。

**2. 防火墙放行（一次性，需要管理员权限）**
双击项目根目录的 `防火墙放行.bat` → 右键"以管理员身份运行"，或手动执行：

```powershell
netsh advfirewall firewall add rule name="skin-health-http"  dir=in action=allow protocol=TCP localport=5173
netsh advfirewall firewall add rule name="skin-health-https" dir=in action=allow protocol=TCP localport=8443
```

**3. HTTPS 与摄像头（浏览器硬性要求）**
非 `https`、非 `localhost` 的页面一律禁止摄像头，局域网 IP 必须走 HTTPS：

- 证书已生成在 `certs/`（CA + 服务器证书，覆盖本机局域网 IP；本机 IP 变化后重跑
  `python tools/make-certs.py` 并重启服务即可）
- `node serve.mjs` 会同时在 `8443` 端口提供 HTTPS
- 每台访问设备需要**信任一次** CA 证书 `certs/ca.crt`
  （通过 `http://<本机IP>:5173/certs/ca.crt` 下载）：

| 设备 | 安装方法（一次即可） |
| --- | --- |
| Android | 手机浏览器打开 CA 链接下载 → 设置 → 安全 → 更多安全设置 → 加密与凭据 → 安装证书 → CA 证书 → 选择下载的文件 |
| iPhone/iPad | Safari 打开 CA 链接 → 允许下载描述文件 → 设置 → 已下载描述文件 → 安装 → 通用 → 关于本机 → 证书信任设置 → 开启完全信任 |
| Windows 电脑 | 下载 `ca.crt` → 双击 → 安装证书 → 本地计算机 → 受信任的根证书颁发机构 → 完成 |

装好后访问 `https://<本机IP>:8443/` 即可正常授权摄像头。

> 若手机连同一 Wi-Fi 却连 `http://<本机IP>:5173/` 都打不开，说明该网络开了
> "AP 隔离 / 客户端隔离"（酒店、校园、公司网络常见），局域网方案无法使用，
> 需要公网 HTTPS 隧道（如 ngrok，需注册免费令牌）或把静态文件部署到免费托管
> （GitHub Pages / Vercel），两种方式都随时可以帮你配。

## 它能测什么

授权摄像头后，算法会把人脸划分为额头、眉间、眼周、鱼尾、颧颊、鼻部、法令纹、口周、下巴等解剖学分区，
在 **CIE-Lab 色彩空间**里计算 12 项可解释指标，并聚合成六个维度：

| 维度 | 数据来源 |
| --- | --- |
| 舒缓度 | 区域性泛红占比、痘印/丘疹密度、颧颊红度偏差 Δa\* |
| 水油平衡 | 镜面反光占比、T 区 / 两颊反光比、皮肤纹理能量 |
| 细腻度 | 纹理高频能量、毛孔/凹凸密度 |
| 均匀度 | 色素暗斑占比、剔除高光后的亮度离散度 σL\*、色彩离散度 |
| 紧致度 | 额头横纹、鱼尾纹、法令纹的边缘密度 |
| 光泽度 | 全脸中位亮度 L\*、黄蓝轴 b\*、粗糙暗沉 |

另有独立的**眼周状态**（下眼睑与颧颊的亮度差）与**肤色判定**（基于 ITA°）。

报告包含：综合评分环、六维雷达图、逐项测量值表格、**热力图影像证据**（可切换泛红/痘印/油光/色斑/毛孔/细纹图层）、
分优先级的护理建议（含具体成分与需要避免的做法）、早晚护理流程、生活方式建议、就医提示、
以及保存在本机的历史趋势图。

## 算法要点

这些是让结果**稳定、可复现、不带肤色偏见**的关键设计，也是本项目与"随手算个 RGB 均值"的区别所在。

1. **尺度归一化** —— 所有滤波半径按人脸像素宽度等比缩放（基准 200px 脸宽）。
   否则同一张脸用 480p 和 1080p 摄像头拍出来，纹理/毛孔数值会差好几倍，跨设备的历史趋势就失去意义。
   测试中 1x 与 2x 分辨率下：油光差异 1.5%、泛红 1.3%、色斑 10%、纹理 14%。

2. **肤色无关的皮肤掩膜** —— 主判据是 YCbCr 色度 + HSV 色相 + 通道序，
   不依赖"R>95"这类绝对亮度阈值。测试覆盖浅/中/小麦/深/很深五种肤色，检出人脸宽度完全一致（极差 0px）。

3. **局部对比而非全局阈值** ——
   - 色斑：与半径随尺度缩放的**局部**肤色基线比较。用全脸基线会被色斑自身拉低，导致"自我掩盖"。
   - 油光：亮度高于全脸基线**且色度被镜面反射冲淡**（油脂膜的物理特征），因此既能抓成片油光也能抓点状高光。
   - 痘印：红度相对**局部**基线的突起，并与暗斑检测互补（测试验证红色痘印不会被误判为暗斑）。

4. **噪声自适应** —— 由 MAD 估计传感器噪声底噪，所有梯度/毛孔阈值随之调整，
   并从纹理能量中扣除噪声贡献。否则噪点多的摄像头会系统性压低所有纹理类分数。

5. **热力图使用 matte 统计** —— 均匀度用的亮度离散度剔除了镜面高光像素，
   避免"出油"被错误地算成"肤色不均"。

6. **多帧聚合** —— 连续采集 3 帧，逐项取中位数抗抖动；并检查帧间包围盒抖动，晃动过大时给出提醒。

7. **采样质量门** —— 对模糊、过暗、过曝、人脸过小、遮挡、角度偏斜分别给出硬性阻断或软性提醒，
   不达标时不会生成误导性的报告（可选择"仍然生成"，报告里会标注）。

## 隐私

- 摄像头画面只存在于页面内存中，关闭摄像头或离开页面立即释放。
- 所有计算在浏览器内完成（Canvas + 手写色彩/滤波算法），**没有任何网络请求**。
- 历史记录（只存分数，不存图像）保存在 `localStorage`，可一键清除。

## 项目结构

```
skin-health/
├── index.html              页面骨架（欢迎 / 相机 / 分析中 / 报告 / 错误 五个步骤）
├── css/styles.css          深色主题 + 打印样式（导出 PDF 用）
├── js/
│   ├── color.js            色彩空间转换（sRGB↔Lab）、盒式模糊、形态学、统计工具
│   ├── vision.js           ★ 分析引擎：皮肤分割 → 人脸定位 → ROI → 指标 + 热力图
│   ├── scoring.js          评分模型、肤质判定、护理建议规则库
│   ├── report.js           报告渲染、雷达图/趋势图绘制、导出
│   ├── history.js          历史记录（localStorage）
│   └── app.js              摄像头授权、实时引导、采集、流程控制
├── serve.mjs               零依赖静态服务器
└── tests/
    ├── synthetic-face.mjs  合成人脸生成器（可指定分辨率，噪声不随几何缩放）
    ├── smoke.mjs           算法测试：差分响应、尺度不变性、肤色公平性、鲁棒性
    ├── dom-contract.mjs    DOM 引用静态校验
    ├── make-y4m.mjs        生成 Y4M 视频，用作无头浏览器的虚拟摄像头
    └── e2e.mjs             真实浏览器端到端测试（CDP 驱动，含响应式与截图）
```

`vision.js` 与 `scoring.js` **不依赖任何 DOM API**，因此可以直接在 Node 里跑测试。

## 测试

```bash
node tests/dom-contract.mjs   # HTML/JS 的 id 引用、导出符号、资源存在性
node tests/smoke.mjs          # 算法管线（合成人脸，纯 Node，无需浏览器）
node tests/make-y4m.mjs       # 生成虚拟摄像头视频（e2e 前置步骤）
node tests/e2e.mjs            # 真实浏览器端到端（需要本机有 Edge/Chrome）
```

算法测试最有价值的部分是**差分响应**：用同一个随机种子生成同一张脸，
只改变一个特征（油光 / 皱纹 / 色斑 / 痘印），要求对应指标严格变差：

```
油光    0.1% → 11.7%   水油平衡 100.0 → 57.5
色斑    0.00% → 1.85%  均匀度   100.0 → 91.0
额头纹路 0.9% → 5.3%   紧致度   100.0 → 93.7
痘印    0.53% → 1.77%  舒缓度   100.0 → 97.9
```

端到端测试用 `--use-file-for-fake-video-capture` 把合成人脸喂给无头浏览器的虚拟摄像头，
自动走完「授权 → 采集 → 分析 → 报告」，断言页面零报错、报告 DOM 与 Canvas 真实渲染、
图层切换交互、响应式无横向溢出，并输出整页截图到 `tests/output/`。

> 若设置了环境变量 `E2E_BROWSER` 可指定浏览器路径；找不到浏览器时 e2e 会自动跳过（退出码 0）。

## 已知限制

- 测量的是**可见光照片上的表面光学特征**，不是医学检查。
- **防晒与光线是最大变量**：颜色类指标（泛红、色斑、光泽度）对光源色温和强度敏感，
  请在相同光线下复测比较趋势，而不是比较绝对值。
- 纹路/毛孔类指标受摄像头分辨率与对焦影响；已做尺度归一化与噪声扣除，但无法完全消除。
- 评分模型是启发式的相对指标，未在大规模临床数据上标定。
- 无法测量：皮肤屏障功能、含水量（仅能用"哑光 + 粗糙"间接推测）、真皮层状态、
  以及任何需要触诊或仪器（如皮脂计、水分笔、皮肤镜）的信息。
